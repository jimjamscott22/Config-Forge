Repo: jimjamscott22/Config-Forge (main @ 3e89893) · reviewed Oct 19, 2026 via GitHub API, read-only

Overview

A local-first Linux desktop app for creating, importing, previewing, validating, translating, backing up and safely applying Ghostty, Kitty and Alacritty configs. It keeps comments, ordering and unsupported settings intact.

Stack: Tauri 2 (Rust, SQLite migrations) + React/TypeScript/Vite, Zustand store, Vitest + Testing Library, Playwright, ESLint/Prettier. Bundles target deb and appimage (src-tauri/tauri.conf.json).

The roadmap in docs/config-forge-implementation-plan.md has 19 tasks. docs/project-status.md says Tasks 1–14 are done and development is paused before Task 15. AGENTS.md asks that this pause be respected and that new work start only on a new request.

What's done

  • Structure-preserving parsers and writers for all three terminals, each with tests (src/adapters/{ghostty,kitty,alacritty}/), plus a registry and translation reports (src/adapters/registry.ts, src/services/translation-service.ts).
  • Rust backend: terminal detection, atomic writes with read-back, backups, and native validation with timeouts (src-tauri/src/filesystem/, process/native_validation.rs). SQLite repositories for projects and snapshots, with retention (src-tauri/src/db/, migrations/0001_initial.sql).
  • Frontend services: project, template, validation and safe-apply logic (generate → validate → diff → confirm → snapshot → backup → write → verify) in src/services/apply-service.ts.
  • UI: Home screen, create/import drafts, a responsive Split Studio, visual controls and a mock terminal preview (src/components/).
  • Tests: per the status doc, 111 Vitest, 32 Rust and 20 Playwright tests passed on Oct 6. I didn't re-run them.

Structure, performance & security notes

  • Security – unrestricted file write: write_file_atomically(target, candidate) is exposed to the frontend and writes to any path (commands/files.rs). create_config_backup also accepts any backup_root. If the webview were ever compromised, it could overwrite any file the user owns. Limit writes to detected config paths and the app-data folder.
  • Security – frontend chooses the binary: validate_candidate takes binary_path from the frontend and runs it (commands/validation.rs). The arguments are chosen by the backend, but the executable isn't. The backend should resolve the binary from its own detection results.
  • Good: there's a strict CSP (tauri.conf.json) and a minimal capabilities/default.json.
  • Performance: SplitStudio runs adapter.generate() and validateProject() on every render with no useMemo. This is fine for small configs but repeats work on every keystroke.
  • Code smells: the imports in tauri-client.ts are split in the middle of the file. AppearanceControls/BehaviorControls/FontControls.tsx are trivial wrappers. @iarna/toml causes build warnings and needs a global shim in Vite. Consider smol-toml.
  • Missing tests: nothing covers IPC end to end, the DB is never initialized at startup, there's no packaged-app smoke test, and no coverage threshold is set (AGENTS.md).

High-impact improvements

Security — Limit write and backup commands to an allowlist of paths, and resolve validator binaries on the backend. Then remove or restrict the raw write_file_atomically command once apply_config is wired up.
Reliability / DevOps — Add a GitHub Actions workflow that runs format, lint, typecheck, Vitest, Playwright, and cargo test/clippy, plus a tauri build job that uploads the deb/AppImage.
Performance — Memoize generate/validate per project revision, and debounce validation while typing in the coming source editor.
UX — One-click "Undo last apply" that restores the most recent backup, and live-reload hints (e.g. Kitty's SIGUSR1 reload).
Feature — Import themes from community sources (base16 or iTerm2 color schemes) into the shared palette model.

Per AGENTS.md, the owner wants to be consulted before new features are added.
